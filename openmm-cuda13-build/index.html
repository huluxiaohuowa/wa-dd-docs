    OpenMM 8.0 + CUDA 13 编译指南

    本文档记录在 Jetson Thor (ARM64 + CUDA 13.0) 上从源码编译 OpenMM 8.0 的完整步骤，包括 CUDA 13 API 变更的 patch。

    背景

    Jetson Thor 使用 CUDA 13.0，但 OpenMM 8.0 官方只支持到 CUDA 12.x。CUDA 13 修改了 cuCtxCreate 函数签名（从 3 参数变为 4 参数），导致 OpenMM 编译失败。

    通过修改 platforms/cuda/src/CudaContext.cpp 中的一处调用，可以让 OpenMM 8.0 在 CUDA 13 上编译通过并正常使用。

    预编译包

    编译好的 native libs/plugins 包保存在 docker/thor/openmm-cuda13-arm64.tar.gz（git lfs 追踪）。当前仓库内的包不包含 Python binding。FEP 镜像通过 conda-forge 安装 OpenFE/OpenMM Python 环境，并默认使用该环境自带的 OpenMM 8.4 插件目录；这里的 OpenMM 8.0 CUDA13 包保留为参考/备用，不作为 OpenFE 镜像默认插件源。

    编译步骤

    1. 环境准备

    # 在 Jetson Thor 上
ssh tc81

# 检查 CUDA 版本
nvcc --version
# 应显示 CUDA 13.0

# 安装编译依赖
sudo apt-get update
sudo apt-get install -y cmake git swig python3-dev build-essential doxygen

    2. 克隆 OpenMM 源码

    cd /tmp
# 国内网络建议使用 ghfast.top 加速
git clone --depth 1 --branch 8.0.0 https://ghfast.top/https://github.com/openmm/openmm.git openmm-src
cd openmm-src

    3. 应用 CUDA 13 patch

    CUDA 13 的 cuCtxCreate 签名变更：

    // CUDA 12.x
CUresult cuCtxCreate(CUcontext *pctx, unsigned int flags, CUdevice dev);

// CUDA 13.0
CUresult cuCtxCreate(CUcontext *pctx, CUctxCreateParams *params, unsigned int flags, CUdevice dev);

    修改 platforms/cuda/src/CudaContext.cpp 第 193 行：

    // 原始代码（CUDA 12.x）
if (cuCtxCreate(&context, flags, device) == CUDA_SUCCESS) {

// 修改后（CUDA 13.0）
CUctxCreateParams ctxParams = {};
if (cuCtxCreate(&context, &ctxParams, flags, device) == CUDA_SUCCESS) {

    可以用 Python 脚本自动 patch：

    #!/usr/bin/env python3
import re

filepath = 'platforms/cuda/src/CudaContext.cpp'
with open(filepath, 'r') as f:
    lines = f.readlines()

with open(filepath, 'w') as f:
    for line in lines:
        if 'cuCtxCreate(&context, flags, device)' in line:
            f.write('            CUctxCreateParams ctxParams = {};\n')
            f.write('            if (cuCtxCreate(&context, &ctxParams, flags, device) == CUDA_SUCCESS) {\n')
        else:
            f.write(line)

print('CUDA 13 patch applied')

    4. 编译

    mkdir build && cd build

# 配置（启用 CUDA + Python 包装）
cmake .. \
  -DCMAKE_INSTALL_PREFIX=/usr/local/openmm-cuda \
  -DOPENMM_BUILD_CUDA_LIB=ON \
  -DCUDA_TOOLKIT_ROOT_DIR=/usr/local/cuda-13.0 \
  -DOPENMM_BUILD_PYTHON_WRAPPERS=ON \
  -DPYTHON_EXECUTABLE=/usr/bin/python3 \
  -DOPENMM_BUILD_SHARED_LIB=ON

# 编译（限制并发数避免内存耗尽，Thor 10GB 内存用 -j2）
make -j2

# 安装
sudo make install

    5. 安装 Python 绑定

    # 创建虚拟环境
python3 -m venv ~/wa-dd-fep-env
source ~/wa-dd-fep-env/bin/activate

# 安装 Cython 和 numpy（OpenMM Python 包装的依赖）
pip install 'numpy<2.0' cython

# 安装 OpenMM Python 绑定到虚拟环境
cd /tmp/openmm-src/build
make PythonInstall

# 验证
python -c "import openmm; print(openmm.__version__)"

    6. 验证 CUDA 平台

    export OPENMM_PLUGIN_DIR=/usr/local/openmm-cuda/lib/plugins
export LD_LIBRARY_PATH=/usr/local/openmm-cuda/lib:$LD_LIBRARY_PATH

python3 -c "
import openmm
platforms = [openmm.Platform.getPlatform(i).getName() for i in range(openmm.Platform.getNumPlatforms())]
print('Platforms:', platforms)
assert 'CUDA' in platforms, 'CUDA platform not found!'

# 测试 CUDA context
import openmm as mm
from openmm import unit
platform = mm.Platform.getPlatformByName('CUDA')
system = mm.System()
system.addParticle(1.0)
integrator = mm.LangevinMiddleIntegrator(300*unit.kelvin, 1/unit.picosecond, 0.001*unit.picoseconds)
import openmm.app as app
sim = app.Simulation(app.Topology(), system, integrator, platform)
print('✓ CUDA simulation created on Jetson Thor!')
"

    7. 打包预编译库

    cd /usr/local
tar -czf /tmp/openmm-cuda13-arm64.tar.gz openmm-cuda/
ls -lh /tmp/openmm-cuda13-arm64.tar.gz
# 约 6.5MB

    8. 安装 FEP 依赖

    source ~/wa-dd-fep-env/bin/activate

# 安装 OpenFE 和相关依赖
# 注意：不要用 pip install openfe；PyPI 的 openfe 是另一个同名特征工程包。
mamba create -y -p ~/wa-dd-fep-env -c conda-forge \
  python=3.11 \
  cuda-version=13.0 \
  openfe=1.12.0 \
  openmm \
  openmmforcefields \
  rdkit
source ~/wa-dd-fep-env/bin/activate
pip install 'fastapi>=0.115.0,<1.0' redis sqlalchemy 'psycopg[binary]>=3.2.0,<4.0'

# 验证完整环境
python3 -c "
import openmm, openfe, rdkit
from openmmforcefields.generators import SystemGenerator
print('OpenMM:', openmm.__version__)
print('OpenFE:', openfe.__version__)
print('RDKit:', rdkit.__version__)
print('All FEP dependencies ready!')
"

    环境变量

    在 Dockerfile 和 worker 启动脚本中设置以下环境变量：

    export OPENMM_PLUGIN_DIR=/usr/local/openmm-cuda/lib/plugins
export LD_LIBRARY_PATH=/usr/local/openmm-cuda/lib:$LD_LIBRARY_PATH

    故障排查

    编译错误：cuCtxCreate 参数不匹配

    确保应用了第 3 步的 patch。检查方法：

    grep -n 'cuCtxCreate' /tmp/openmm-src/platforms/cuda/src/CudaContext.cpp

    应该看到 cuCtxCreate(&context, &ctxParams, flags, device) 而不是 cuCtxCreate(&context, flags, device)。

    Python 导入错误：No module named 'openmm'

    # 检查 Python 绑定是否安装
python3 -c "import sys; print(sys.path)"
ls /usr/local/openmm-cuda/python/openmm/

# 确保 PYTHONPATH 包含 OpenMM Python 目录
export PYTHONPATH=/usr/local/openmm-cuda/python:$PYTHONPATH

    CUDA 平台不在可用列表中

    # 检查插件目录
ls /usr/local/openmm-cuda/lib/plugins/
# 应该有 libOpenMMCUDA.so

# 手动加载插件
python3 -c "
import openmm
openmm.Platform.loadPluginsFromDirectory('/usr/local/openmm-cuda/lib/plugins')
print([openmm.Platform.getPlatform(i).getName() for i in range(openmm.Platform.getNumPlatforms())])
"

    NumPy 版本冲突

    OpenMM 8.0 要求 NumPy < 2.0：

    pip install 'numpy<2.0'

    预编译包内容

    openmm-cuda13-arm64.tar.gz 解压后当前包含 native libs/plugins：

    /usr/local/openmm-cuda/
├── bin/
│   └── TestOpenMM              # 测试程序
├── include/
│   └── OpenMM.h               # C++ 头文件
├── lib/
│   ├── libOpenMM.so           # 主库
│   ├── libOpenMMAPI.so
│   ├── libOpenMMCuda.so       # CUDA 平台库
│   └── plugins/
│       ├── libOpenMMCUDA.so   # CUDA 插件
│       ├── libOpenMMCPU.so    # CPU 插件
│       └── libOpenMMOpenCL.so # OpenCL 插件
